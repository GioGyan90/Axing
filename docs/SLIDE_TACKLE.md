# 滑铲动作与碰撞

2026-11-13，在原单人挑战和 5v5 八角笼模式加入 R / 触屏“滑铲”。Space 射门 / 站立抢断、F 踢人、E 传球、Q 切换保留。

- 沿按下时的移动方向滑出；静止时沿面朝方向。滑行期间方向固定，不能用鼠标或反向输入瞬间转弯。
- 滑行 0.60 秒，逐渐减速，无遮挡水平距离 2.7 米；整个动作含起身 0.84 秒，滑铲冷却 1.8 秒。
- 在 0.08–0.60 秒伸腿阶段，按脚前段的胶囊范围与目标的相对运动检查整段路径。低球可被铲离脚下并滚向滑行方向；高球、身后与侧方未接触的目标不会被隔空命中。
- 一次滑铲可以铲球并放倒对手；同一个球、同一名对手在同一动作中最多触发一次。不铲倒队友，不给已眩晕的人反复延长眩晕。
- 铲倒保留原倒地、3.9 秒眩晕、0.6 秒起身与星星提示。只铲球不吹罚；铲人被场外裁判看见时，5v5 判给对方任意球，单人挑战使用已有犯规结果；AI 犯规将球权还给玩家，不扣玩家机会。
- 球员身体受原球场 / 八角笼边界约束。暂停冻结滑行；进球、半场、点球准备、重开与终场清除动作和未来接触。

## 动作来源

复用原人物身体和头部，没有换模。新增 motion-plan v1 `slide`，手型标为 open，经用户指定的 [3D_AItool](https://github.com/GioGyan90/3D_AItool) Prompt2Rig 编译、重定向到足球骨架，固定源码 `0434ddfaee268531cf6141b8cbf19c6d64c2decf`。上游仓库未修改，没有另行调用收费 API。

源方案在 `tools/football-plans.mjs`，生成的完整 JSON 和动画在 `scripts/game/motions/`。构建方式沿用 [足球动作接入](FOOTBALL_MOTION.md)。`motion-review.html` 的“伸腿滑铲与起身”可逐时刻观察六个视角；实际身体网格做接地校正。侧面复查后加大非伸展腿的屈膝，降低臀部，避免身体悬高。

水平位移与脚部碰撞在 `scripts/game/slide-tackle.js` 共用；单人接入在 `single-slide.js`，5v5 接入在 `scripts/five/engine.js`。Three.js 和 Canvas 兼容画面使用同一个比赛状态。Canvas 以方向投影的低身姿势表现伸腿与起身。

## AI

双方自动控制的场上球员、单人困难后卫会在低球与敌方持球威胁附近判断滑铲；不针对队友，门将继续保留扑救和近身踢人。出手前约 0.3 秒红色 ! 预警，可移动闪避。滑铲锁定预判方向；之后躲开不会受到追踪命中。裁判视野内降低尝试概率，沿用个人 6–9 秒与同队 3.2 秒的对抗间隔。近距离踢人、正常传射优先级保留。

## 验证

新增 14 项专项检查，连同之前 74 项合计 88 项：10 / 30 / 60 / 120 Hz 滑行距离，运动方向与恢复，快速相对运动接触，高球 / 侧后方不命中，铲球与铲人，单次命中，边界与暂停 / 半场 / 点球清理，双方 AI 与单人后卫自主决策，裁判判罚和原人物 169 个滑铲姿态的网格接地、伸腿、低身及相邻帧连续性。

浏览器使用真实按钮、R 键检查只铲球、铲球并铲人、犯规和 AI 滑铲；真实 390×844 / 844×390 iframe 检查移动端布局。动作检查页使用原人物和同一个烘焙片段。当前云浏览器无 WebGL，因此比赛画面用 Canvas 兼容渲染，原人物用 Canvas CPU 预览；GPU WebGL 路径通过模块 / 数值检查，未做实际 GPU 画面验收。
